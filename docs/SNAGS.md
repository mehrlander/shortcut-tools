# Snags

Things tripped over here, noted so the next session trips once rather than three
times. Each entry is a slug, one line naming the symptom and the corrected move,
a `seen:` line of dates, and a `→` to the document that carries the actual fix.
Newest on top. An entry stays an index line, so it cannot drift from the doc that
holds the fix.

**Recurrence is the signal, and it is counted mechanically.** A trip already here
belongs in the entry that owns it, as another date on its `seen:` line, never as a
second entry. `python3 tools/snags-index.py --publish` rewrites the table below
and `--check` holds it, the same contract `packed/`, `plists/` and `catalog.json`
each run. A hand count is the number a session gets wrong, and a wrong count in
the place that claims to measure repetition is worse than none.

**What this keys on**, distinct from the other stores here: the tracker keys on a
task, which is intent; `docs/shortcuts-format-notes.md` keys on a fact about the
file format, which is durable; this keys on a **trip**, which is atomic and
crosses branches. A snag that keeps recurring graduates to a tracker task that
removes the cause.

**Backfilled 2026-09-14** from one long session and the branch behind it, so the
dates below are when the trip was *identified*, which for the older ones is later
than when it happened. Nothing before that session is here yet, and its absence
is not evidence that nothing happened.

## splice-drops-file-level-settings

A chain derived by splicing another shortcut's actions carried no `workflow` block, so the published plist declared no `WFWorkflowNoInputBehavior` and every back tap arrived with Shortcut Input empty, unnoticed for a fortnight. Diff the top-level keys, not the action lists.
seen: 2026-09-14
→ `docs/shortcuts-format-notes.md`, "A splice that keeps the actions still loses the shortcut's settings".
